# Customer Input Mapping Contract

Version: v0.1

Release: Public

## 1. Purpose

This document is a reusable mapping template.

The semantic roles below are a reference-derived role catalog, not a mandatory physical schema and not a requirement that every customer expose the complete role set.

Only roles selected by the customer's governance capabilities and applicability rules must be bound.

## 2. Customer completion fields

For every selected role, the customer completes:

- `CUSTOMER_FIELD_BINDING`
- `CUSTOMER_SOURCE_BINDING`
- `CUSTOMER_TRANSFORM_BINDING`
- `CUSTOMER_PROVENANCE_BINDING`

The customer may use a field, event property, object attribute, API value, record, stream value, or another equivalent representation.

## 4. Mapping rules

1. Do not copy a reference field name merely to satisfy a role.
2. Bind the customer's native representation that actually carries the required semantic fact.
3. Record source and provenance for every bound role.
4. Declare transforms explicitly.
5. Required roles are required only when the selected capability and applicability contract make them applicable.
6. Optional roles may remain unbound.
7. Cardinality is implementation-defined.
8. A customer mapping cannot redefine governance-derived or governance-generated authority.

## 5. Customer-instance completion

The generic template is complete.

A customer instance remains intentionally incomplete until customer-specific bindings are supplied and verified.
